Simulation

In 2024, I wrote my own 3D physics engine in C++. At one point, I had a virtual towel hanging in the simulator, and I spent a while throwing balls at it just to watch the constraints wobble. It was one of several experiments I made while exploring physics simulation and computer graphics.

Physics engine

The engine used Verlet integration, storing current and previous particle positions to calculate motion. I implemented collision detection and resolution, link and rigid constraints, and a three-dimensional collision grid to avoid checking every possible pair of objects. I also added world serialization and experimented with parallel simulation updates.

The physics was entirely my own implementation. For the surrounding application, I used native OpenGL, SFML, Eigen and Dear ImGui, which helped with rendering, interaction and debugging.

Voxel renderer

Playing Teardown made me curious about voxel rendering. I experimented with grid traversal and ray intersections, implementing material handling for reflection, refraction, diffuse surfaces and emissive voxels. Unlike the physics engine, parts of the surrounding OpenGL/OpenCL infrastructure came from an existing template.

First, I started with [a href="https://jacco.ompf2.com/2024/04/24/ray-tracing-with-voxels-in-c-series-part-1/"]this tutorial[/a] (thanks a lot for this! One of the best introductory voxel raytracing resources I have come across) to learn graphics programming in April of 2025. To make it run on Apple Silicon, since this specific renderer ran on the CPU, I rewrote a header library that was using x86 SIMD to use ARM Neon. It ran great!

[video src="http://cdn.morisinc.net/first_vox_renderer.mp4"]First ever Voxel Renderer[/video]

Then started experimenting myself with other stuff, like just after finishing said tutorial, trying to harness some of the GPU's power, and that's how I learned GLSL. Still under OpenGL.

Other experiments

I also explored ray tracing, deferred rendering, path tracing and subdividing spatial grids. Some experiments went further than others, and a few were left rather messy. What interested me was understanding how the algorithms actually worked, from representing objects in memory to finding out which calculations became expensive.

I didn't really publish the code for all of this, because I usually publish source code when the project's in a good shape and not just a random experiment of mine.
